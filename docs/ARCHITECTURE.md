# NEXORA OS Architecture

## Overview

NEXORA OS is a Debian-derived operating system assembled with Debian Live `live-build`. Its first desktop edition targets Debian 13 Trixie on amd64 and uses a deliberately small XFCE4 session.

## Layers

1. **Debian base** — Debian packages, kernel, systemd and essential utilities.
2. **Live image** — hybrid bootable filesystem generated by live-build.
3. **Desktop** — XFCE4 session, panel, window manager, Thunar and LightDM.
4. **NEXORA identity** — custom GTK theme, wallpaper, greeter and Welcome launcher.
5. **Software delivery** — APT for the base OS and Flatpak/Flathub for optional user applications.
6. **NEXORA Store** — a small GTK3/Python interface over Flatpak, using a version-controlled curated catalog rather than a heavyweight desktop software center.

## Desktop design

- XFCE4 is the only desktop environment in the initial desktop image.
- LightDM with GTK greeter replaces SDDM.
- NEXORA dark GTK styling and wallpaper are installed as system assets.
- New users receive NEXORA XFCE settings through `/etc/skel`.
- A lightweight PolicyKit agent handles privileged Flatpak operations.
- APT recommended packages are disabled to avoid optional dependency growth.

## Software policy

- No games are preinstalled.
- No heavyweight game launchers or desktop software centers are included.
- Flatpak is installed and Flathub is configured as a system remote.
- NEXORA Store provides search, categories, install, remove and system-wide updates for its curated app catalog.
- Games appear only as optional catalog entries and are downloaded only after the user chooses Install.
- The catalog is maintained in `config/includes.chroot/usr/share/nexora-store/catalog.json`.

## Editions

- **Desktop:** Hyper Lightweight XFCE4; current development target.
- **Server:** server-focused package selection; planned.
- **Core:** minimal base for custom deployments; planned after Desktop stabilizes.

## Build flow

```text
Git repository
    |
    v
auto/config + package manifest + includes + hooks
    |
    v
Debian live-build
    |
    v
bootable amd64 ISO
    |
    v
CI validation and virtual-machine testing
```

## Design constraints

- Prefer Debian packages and upstream software without modifications.
- Keep NEXORA-specific defaults version-controlled and reviewable.
- Avoid credentials, private keys and machine-specific settings.
- Keep the base image modular and avoid unnecessary background services.
- Preserve upstream copyright and license notices.
- Do not claim an ISO is tested until a build and boot test actually pass.
